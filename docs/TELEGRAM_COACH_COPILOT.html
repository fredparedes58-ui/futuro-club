VITAS Coach Copilot

El chatbot de Telegram que responde sobre tus datos reales

Qué es

El VITAS Coach Copilot es un bot de Telegram al que el coach habla en lenguaje natural y responde con datos reales del coach que pregunta — no genéricos. Vive en Telegram (no en la web aún), y es el primer y único chatbot conversacional de VITAS hoy.

Ejemplos de preguntas reales:

Coach
"¿Cómo va Samu este mes?"
Coach
"Dame los stats del último partido"
Coach
"¿Qué drills recomiendas para mejorar el primer toque?"
Coach
"¿Está en PHV alguno de mis chavales?"
Coach
"Lista mis jugadores ordenados por VSI"

Ejemplo del flujo "¿cómo va Samu?"

Coach
"¿cómo va Samu este mes?"
Claude (razonamiento interno)
Necesito datos de Samu. Llamo a list_players para encontrar su ID.
Tool call
list_players({}) → [{id: "p1", name: "Samu", ...}]
Claude (razonamiento)
Samu = p1. Ahora get_player con sus datos completos.
Tool call
get_player({playerId: "p1"}) → VSI 72, PHV +1.2, último análisis 5 días atrás...
Bot al coach
"Samu está bien este mes. VSI 72 (+3 vs mes pasado), PHV en zona on-time (+1.2). Último partido hace 5 días, fatiga normal. Su scanning subió 8 puntos por trabajo en rondos del Drill TEC-001."
Clave: Claude no inventa datos. Si pregunta algo que no tiene tool para resolverlo, dice que no lo sabe. Si los datos no existen en BD, devuelve "no tengo datos sobre eso".

Multi-turn (conversación con memoria)

Turn 1 — Coach
"¿Cómo va Samu?"
Bot
"VSI 72 (+3 mes), PHV on-time, fatiga OK..."
Turn 2 — Coach
"¿Y vs el mes pasado?"
Bot (sabe que es Samu sin repetir)
"Subió 3 puntos en VSI..."
Turn 3 — Coach
"Recomiéndame drills"
Bot (sabe contexto Samu + scanning bajo)
"Para mejorar..."

El bot recuerda los últimos N turnos vía la tabla telegram_messages (cada mensaje persiste con chat_id, role, content). Trunca cuando se acerca al límite de context window.

Identificación del coach (onboarding)

1. Coach va a /settings → ve componente TelegramConnect 2. Click "Conectar Telegram" ↓ 3. Backend genera UUID v4 → INSERT en telegram_link_tokens (TTL 10 minutos, single-use) ↓ 4. Devuelve URL: https://t.me/VitasCopilotBot?start=<UUID> ↓ 5. Coach abre el link en Telegram → ejecuta /start <UUID> ↓ 6. Webhook resuelve UUID → vincula telegram_chat_id ↔ user_id INSERT en coach_telegram_mapping ↓ 7. Token consumido. Bot ya sabe quién es ese chat.

A partir de aquí, cada mensaje que el coach manda lleva su telegram_chat_id → el backend resuelve a user_id → todas las tools que llama Claude se filtran por ese user_id (defensa en profundidad con RLS de Supabase encima).

Aislamiento de datos (RLS)

Si dos coaches distintos preguntan "lista mis jugadores", cada uno recibe solo los suyos porque:

  • El service role del webhook respeta el tenant_id del chat
  • Las queries SQL filtran por tenant_id = X
  • RLS de Supabase es defensa #2: si el filtro app-side fallara, RLS bloquearía

Stack técnico

  • Modelo: Claude Haiku (rápido, barato, suficiente para tool use simple)
  • Runtime: Vercel Edge Function (latencia mínima global)
  • Bot: @VitasCopilotBot en Telegram (creado vía BotFather)
  • Auth: bearer token + secret_token header al setWebhook
  • Persistencia: Supabase (3 tablas) + service role bypass RLS desde Edge Function
  • Rate limit: max 30 mensajes/min por chat (anti-spam)
